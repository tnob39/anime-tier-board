#725 child P0 · First action

データを取る前に、取ってよいかを確定

各ソース・各フィールドを allowed / permission-required / prohibited / unknown に分類。unknownは収集停止。

  • 商用・再配布・画像・TTL・帰属
  • 規約とrobotsの変更検知
  • 許可済み最小フィールド
  • 削除要求とkill switch
#726 child P0 · First action

投稿量より先に、運用規程

UGCは明示同意、最新話は48時間配慮。無許諾の画像・映像・音源・切抜きは使わない。媒体順は X → TikTok → Instagram → YouTube。

  • UGC同意と撤回導線
  • ネタバレ・サムネ規則
  • 炎上時の停止SLA
  • 4媒体の規約確認日
#724 child P0 · First action

コードより先に、提携条件

ASP審査、成果地点、否認、Cookie期間、PR表記、商標制約まで比較して、最初のPoC候補を選ぶ。

  • 優先候補5社以上
  • 一次資料URLと確認日
  • 未承認リンクの無効化
  • 採択・却下理由

優先度の区別: Epic優先度（#722=P0 / #723=P1 / #721=P1）はプログラム順序。child P0（#725 / #726 / #724）は各Epic内の最初の実行単位であり、Epic全体の優先度と同じ意味ではない。

Dependency chain

Data → Growth → Revenue

開始条件・blocker・handoff成果物を明示。前段が未達なら後段を単独最適化しない。

01 / DATA

#722 Catalog API

開始条件ソース別利用条件の一次資料があること。unknownフィールドを本番収集しない方針が合意されていること。

handoff成果物利用条件台帳、許可済み最小フィールド、provenance schema草案、100→1,000 PoC判定票。

#723 90日 SNS

handoff成果物週次カレンダー、投稿テンプレ、UTM付きファネル数値、4週判定（CTR/CVR）、次四半期Go/Stop提案。

Data architecture

収集から公開まで

公式APIと書面許諾を優先。品質ゲートの前に権利ゲートを置きます。

01 / Sources公式API・許諾済みフィード・許可された限定収集
02 / Raw vault非公開・短期TTL・取得時の規約versionを固定
03 / Normalize共通schema、identity照合、差分更新
04 / Quality gate欠損・重複・鮮度・権利状態。NGはquarantine
05 / Catalog API認証・rate limit・予算上限・監査ログ
収集原則: 公式API → 書面許諾 → 規約とrobotsが許す限定収集。無断スクレイピング、原文ダンプ再配布、画像の無許諾保存は採用しない。

Decision gates

進む条件、止まる条件

全体ゲートに加え、Epic別のGo/Stopを分離表示します。安全性は成長率より優先。

GO（全体）

  • 収集条件が明確で出典を逆引きできる
  • SNS CTR 0.5%以上 / Tier作成CVR 1%以上
  • Affiliate CTR 3%以上 / ASP差異10%以内
  • 予測粗利が追加費用を上回る
  • 重大な権利・法務違反 0

STOP / REWORK（全体）

  • 規約・商用条件がunknown
  • 削除要求に追従できない
  • 4週・各形式10投稿後も基準未達
  • 提携審査不通過、性能・採算未達
  • 権利侵害・重大炎上は即時停止
